# Подключение админки к Supabase

Сайт остаётся статическим и размещается на GitHub Pages. Supabase обслуживает вход, базу содержимого и медиатеку. Отдельный сервер и сборка не нужны.

## 1. Создайте проект

1. Создайте проект на https://supabase.com/dashboard.
2. В настройках подключения проекта найдите Project URL и публичный Publishable key (либо legacy anon key).
3. В config.js заполните supabaseUrl и supabaseKey. Пример:

```js
window.SITE_CONFIG = {
  supabaseUrl: 'https://PROJECT_REF.supabase.co',
  supabaseKey: 'sb_publishable_ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ'
};
```

Публичный ключ можно размещать в GitHub Pages. Пароль базы, service_role и sb_secret в сайт не вставляются. Доступ защищают политики базы, а не сокрытие публичного ключа.

## 2. Подготовьте базу

В SQL Editor нового проекта выполните содержимое supabase/schema.sql. Скрипт создаёт:

- site_content: опубликованное содержимое единственной страницы;
- site_admins: список пользователей, которым разрешено редактирование;
- функции проверки прав и публикации;
- публичную медиатеку site-media с загрузкой только для администратора;
- RLS: посетители читают опубликованную страницу, изменения разрешены только назначенным администраторам.

Повторный запуск скрипта не сбрасывает уже опубликованное содержимое. Предназначен для отдельного проекта или базы без одноимённых таблиц и политик.

## 3. Создайте администратора

1. В Authentication → Users создайте пользователя со своим email и надёжным паролем. Используйте подтверждённого пользователя (Auto Confirm при создании через панель).
2. В SQL Editor отдельно выполните, заменив email:

```sql
insert into public.site_admins(user_id)
select id from auth.users where email = 'your@email.ru'
on conflict (user_id) do nothing;
```

3. Проверьте, что строка действительно добавилась:

```sql
select a.user_id, u.email
from public.site_admins a
join auth.users u on u.id = a.user_id;
```

Обычный зарегистрированный пользователь без записи в site_admins не может публиковать изменения или загружать изображения. В админке нет самостоятельной регистрации и выдачи прав. Не добавляйте политику, разрешающую всем authenticated обновлять страницу.

Пароль администратора можно изменить через панель Supabase. Сеанс редактора хранится только в памяти вкладки: после её обновления войдите заново. Пароль в файлы сайта не записывается.

## 4. Разместите сайт

Загрузите содержимое папки teplomaterial в корень репозитория, включая admin.html, admin.js, admin.css, cms.js, config.js, product-data.js и assets. Включите GitHub Pages из ветки main и корня репозитория согласно README.md.

Нажмите небольшую иконку пользователя в правой части шапки или откройте /admin.html относительно адреса сайта. Войдите созданным пользователем. Выберите раздел, внесите правки, откройте предпросмотр и нажмите «Опубликовать изменения».

Первая публикация сохранит в базу все исходные тексты. Последующие изменения содержимого не требуют повторной загрузки файлов на GitHub. При проблемах с Supabase посетитель увидит встроенную версию из index.html.

Содержимое хранится как JSON, не как HTML. Редактор поддерживает переносы строк, тексты, изображения, email и телефон, характеристики изделий, заголовок страницы, описание и цвет акцента. Загрузка изображений: PNG/JPG/WebP/AVIF до 5 МБ. Загружаемые файлы публичны сразу после загрузки, даже до публикации страницы. Удаление не используется: новая версия изображения получает новый адрес.

Вход и запись в базу работают по HTTPS. Все изменения проверяются RLS на стороне Supabase. Публикация проверяет номер версии, чтобы обнаружить одновременное редактирование из нескольких вкладок. Публично доступны только опубликованные данные; черновик остаётся в браузере.

## 5. Локальная проверка без Supabase

Из папки сайта запустите:

```text
python -m http.server 8080
```

Откройте http://localhost:8080/admin.html и нажмите «Открыть локальный редактор». Эта возможность отображается только на localhost/127.0.0.1, а не на публичном домене. Локальный режим не является авторизацией и не имеет доступа к Supabase.

Внесите правки и нажмите «Сохранить локально». Главная страница на том же адресе и в том же браузере покажет эту локальную версию. Исходные HTML файлы и сайт в интернете не меняются. Используйте один и тот же адрес (localhost и 127.0.0.1 имеют разное хранилище).

Кнопка «Экспорт JSON» сохраняет резервную копию содержимого. «Импорт JSON» возвращает эту копию в черновик редактора; после проверки нажмите «Опубликовать изменения» или «Сохранить локально». Автоматический черновик также сохраняется в локальном хранилище браузера и восстанавливается при следующем входе. Экспорт — резервная копия данных, не готовый HTML сайт.

## Ограничения и проверка перед запуском

Проект Supabase ещё не создан, поэтому реальный вход, RLS и загрузку в Storage необходимо проверить после настройки:

1. Посетитель без входа видит опубликованную страницу.
2. Назначенный администратор входит, публикует тестовую правку и видит её после обновления.
3. Пользователь без записи в site_admins получает отказ во входе в редактор.
4. Прямая попытка записи с публичным ключом без сеанса администратора отклоняется базой.
5. Изображение загружается администратором и видно посетителям.

SEO метатеги меняются в браузере. Поисковики и социальные сети могут читать исходный HTML: для надёжного обновления карточки ссылки продублируйте title/description/og теги в index.html перед загрузкой на GitHub.

Опубликованное содержимое загружается по постоянным data-cms идентификаторам. Не перенумеровывайте их при ручной правке index.html. При недоступности сети выводится встроенный вариант сайта.
